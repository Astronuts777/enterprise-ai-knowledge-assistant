## 本轮补齐：企业成员停用与恢复

之前只有全局账号 `status` 校验和“强制下线”，没有完整的企业级成员停用入口，不能算已完成。
现在企业管理员可在“成员”页点击“停用成员”或“恢复成员”，并在确认框看到影响范围。
后端接口是 `PATCH /v1/tenants/{tenant_id}/members/{user_id}/status`，请求体为 `{"active": false}` 或 `true`。

- 停用在每次企业资源请求时生效，旧 Cookie 不能继续读取、检索或上传该企业资料。
- 不全局删除账号或会话，不影响该用户在其他企业的权限；已发给客户端的内容无法远程收回。
- 保留角色与空间授权，恢复会重新启用原权限；恢复前应复核是否仍合适。
- 不允许管理员停用自己；未授权/跨企业访问被拒绝；重复邀请或普通成员保存接口不能绕过停用。
- 记录 `membership.suspended` / `membership.restored` 审计；同企业状态修改串行化并在加锁后复核操作者权限。
- 增加迁移 `20261022_0011`，已有成员默认为启用，保留空间授权；升级前先备份。
  本地启动器自动迁移，已有运行中的服务须重启，网页须重新构建；本轮未更新线上站点。

## 本轮补齐：本地加密备份与隔离恢复

无需 PostgreSQL、云存储或新增服务。工具：`enterprise_ai_api.local_backup`。
支持本地 AI 启动器生成的 SQLite 工作区，内容上限 128 MiB、最多 10,000 个文件；超过上限会拒绝，
不要把它当成大规模生产备份系统。备份在内存里组装/加密，可能使用数倍于内容大小的内存。

备份包括：数据库一致性快照（包含已提交 WAL 数据）、所有数据库引用的加密原件、应用主密钥。
未被数据库引用的孤立文件不会纳入备份；模型可重新下载，不纳入备份。
每次创建/验证都会检查 SQLite 完整性及外键、加密字段能否解密、原件路径/大小/指纹和清单哈希。
原件丢失、密钥错误或数据损坏时不会产生一个“成功”的备份。

先停止 Web＋API＋Worker，避免在业务操作中执行备份和切换。以下命令在仓库根目录运行：

```bash
export PYTHONPATH=services/api/src:packages/core/src
mkdir -p data/local/backups data/local/backup-keys

# 只执行一次。若文件已存在会拒绝覆盖；不要为旧备份替换密钥。
.venv/bin/python -m enterprise_ai_api.local_backup keygen \
  --key-file data/local/backup-keys/local-backup.key

# 每次使用新的输出文件名。
.venv/bin/python -m enterprise_ai_api.local_backup create \
  --key-file data/local/backup-keys/local-backup.key \
  --output data/local/backups/pilot-001.local-backup.enc

.venv/bin/python -m enterprise_ai_api.local_backup verify \
  --key-file data/local/backup-keys/local-backup.key \
  --archive data/local/backups/pilot-001.local-backup.enc

# 仅恢复到一个尚不存在的新目录，绝不会覆盖当前工作区。
.venv/bin/python -m enterprise_ai_api.local_backup restore \
  --key-file data/local/backup-keys/local-backup.key \
  --archive data/local/backups/pilot-001.local-backup.enc \
  --target data/local/pilot-restore-001
```

备份密钥不同于 `data/local/ollama/master.key`。备份文件内包含原应用密钥，外层由独立备份密钥加密。
丢失备份密钥将无法恢复。示例目录仍在同一硬盘上，**不具备硬盘故障容灾能力**：
请将备份和备份密钥分开保存在已有、受控的备份介质上，不上传 GitHub，也不要把两者一起公开。
没有配置定时任务或自动删除策略，需人工定期执行并留存多个恢复点。

恢复命令不切换运行实例。检查隔离目录后，如确需恢复业务，先停止所有服务、保留原工作区安全副本，
再由管理员将整套恢复目录及原应用密钥安装到 `data/local/ollama`。重新登录、读取文档、打开引用并检查权限。
恢复写入中断时可能留下部分新目录；不要使用它，应保留原业务数据并使用另一个新目录重试。

## 本轮补齐：免费、本地恶意文件扫描接入

适配的是自托管 ClamAV，不调用第三方扫描 API，也不把文件发到公网。
默认 `FILE_SCAN_BACKEND=disabled` 是为了保持个人安装兼容，**不代表已经扫描或安全**。
进入企业试点前应明确启用，更新病毒库，并完成真实验收。

已有适合本组织使用的容器运行时时，可单独启动扫描服务（不启动其他基础设施）：

```bash
docker compose -f infra/clamav-compose.yml up -d
docker compose -f infra/clamav-compose.yml logs --tail=50 clamav
```

可使用已有的 Linux Docker Engine；不要为本项目购买 Docker Desktop，使用其他运行时时自行核对兼容性及许可。
也可直接安装原生 ClamAV，让 `clamd` 仅监听 `127.0.0.1:3310`，通过 `freshclam` 更新病毒库。
容器配置使用 1.4 分支，实际试点需复核该分支支持状态及镜像补丁、记录镜像摘要。
官方建议 ClamAV 至少 3 GiB、优选 4 GiB 内存；和本地模型一起运行需要额外容量。
参见 [ClamAV 安装说明](https://docs.clamav.net/manual/Installing/Docker.html)。

启动网页前设置（启动器会继承这些变量，不自动读取 `.env`）：

```bash
export FILE_SCAN_BACKEND=clamav
export FILE_SCAN_REQUIRED=true
export CLAMAV_HOST=127.0.0.1
export CLAMAV_PORT=3310
export CLAMAV_TIMEOUT_SECONDS=30
.venv/bin/python scripts/local_ai.py start
```

行为约束：

- 先验证企业和空间权限，再扫描；未授权请求不会把文件送给扫描服务。
- 新文件、新版本均先扫描，随后才保存加密原件、解析/OCR、创建向量。
- 只有明确的完整 `stream: OK` 响应才放行；风险返回 422；超时、断线、格式错误或扫描限额返回 503，均阻止上传。
- 拒绝事件写入审计，但不写文件正文、文件名、病毒签名细节或扫描器原始报错。
- 上传扫描发生在应用本机，不新增明文临时文件；ClamAV 自身解析可能使用临时文件，需保护其运行环境与磁盘。
- TCP 无认证，因此适配器只接受字面量回环 IP，容器端口也只映射到回环地址；不能暴露 3310 到公网。
- 配置生产门禁只是静态检查；不会验证病毒库新鲜度，现有历史文档不会自动重扫。
  试点前需要清点历史资料并重新上传扫描后的新版本，不能把旧资料标成已经扫描。
- 检出范围取决于病毒库、引擎和配置；扫描不是绝对安全保证，也不能替代解析沙箱。

协议依据：[ClamD INSTREAM 协议](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)。
正式验收应在隔离测试空间使用官方无害测试样本验证拦截，并验证断开扫描服务时上传被拒绝；本轮仅用模拟协议响应做自动化测试。

## 后续实现顺序与进入试点的门槛

1. 已实现持久队列与 Worker；下一步在实际设备验收重启续跑、扫描/模型故障、队列积压及企业文件处理耗时。
2. 已有企业邮箱与共享部署：接入实际 SMTP 并验收；使用已有内网设备规划访问和备份，不自动开通收费服务。
3. 监控闭环：确定告警接收人，配置定期备份及恢复演练，验证模型、扫描器和数据库故障告警。
4. 按 `10-worker-sso-scim.md` 对接企业已有或自托管 IdP，验证 OIDC/SCIM 兼容性；未联调前不得宣称真实企业身份服务已启用。
5. 先用脱敏资料进行权限、恢复、文件安全和回答质量验收；满足门槛后再邀请 1–3 家企业。

最低试点验收：

- 管理员、普通成员、未授权空间成员、另一企业用户分别测试；撤销权限/停用后立即失去访问。
- MFA 恢复流程可操作，验证/邀请/重置令牌过期和重复使用都失败。
- 服务重启后原件仍存在；独立恢复目录能登录、读取文档，并验证备份密钥的离线可用性。
- 扫描服务故障必须拒绝新上传；OCR 失败不能发布成完整内容；失败任务可见且不无限重试。
- 用中文/英文、同义词、跨文件问题和无依据问题评测，记录引用正确率、拒答和等待时间。
- 指定每家试点负责人、资料范围、评测标准、故障联系人，以及试点结束后的导出/删除安排。

本轮没有接触真实企业文件、发送邀请、配置公网域名、启动付费服务或触发 Render 部署。
