# 安全、身份与加密设计

## 访问模型

系统把“证明你是谁”和“允许你做什么”分开处理：

1. 用户通过邮箱密码注册，并在启用生产邮件验证时使用限时、一次性链接证明邮箱所有权。
2. 登录后服务端签发随机会话令牌；浏览器只在 HttpOnly Cookie 中持有原始令牌。
3. 数据库仅保存令牌的带密钥摘要，会话默认 12 小时过期，退出时服务端删除会话。
4. 创建企业的账号自动成为企业管理员。
5. 加入已有企业只能使用管理员针对指定邮箱创建的邀请；邀请七天过期且只能接受一次。
6. 每个业务请求都重新检查用户、企业成员关系、企业角色和空间授权，不信任浏览器提交的角色。
7. 跨企业或未获授权的跨空间访问统一返回不暴露资源存在性的错误。

用户不能在注册时自行选择管理员角色，也不能通过输入企业名称加入已有企业。

## 角色

| 角色 | 主要权限 |
| --- | --- |
| 企业管理员 | 管理成员、邀请和全部空间，不受空间 ACL 限制 |
| 知识管理员 | 创建空间；创建后自动成为该空间管理员 |
| 普通成员 | 只访问明确授权的知识空间并提问 |

空间 ACL 另设 `manager` 和 `viewer` 两种角色。`manager` 可以管理空间授权以及上传、预览、发布和更新文档；
`viewer` 只能读取已发布资料并提问。撤销空间授权后，空间列表、文档、检索结果和带有该空间引用的历史回答都会立即隐藏。

文档阅读接口不会信任前端隐藏按钮，而是在服务端依次验证登录会话、企业成员关系和知识空间授权。
`viewer` 的文档列表与阅读器只返回最近一个已发布版本；空间 `manager` 和企业管理员可以预览当前草稿。
没有空间授权、跨企业访问或普通成员试图读取仅有草稿的文档时，接口统一返回不暴露资源是否存在的错误。

## 密码和会话

- 密码至少 12 个字符，使用 scrypt 和每个账号独立的随机盐做单向哈希。
- 登录失败统一返回 `Invalid credentials`，不暴露邮箱是否存在。
- 失败登录按账号和网络来源分别记录：账号 15 分钟内最多 5 次，网络来源 15 分钟内最多 50 次。
- 会话令牌由密码学安全随机数生成，数据库只保存带密钥摘要。
- Cookie 使用 HttpOnly、SameSite=Lax；非开发环境启用 Secure。
- 用户可以查看当前账号的全部有效会话、退出指定设备或一次退出全部其他设备；当前设备由令牌摘要精确识别。
- 企业管理员可以强制撤销当前归属本企业成员的全部登录会话，但不能影响当前归属其他企业的账号；操作会进入追加式审计日志。
- 设备标签只保留粗粒度浏览器和操作系统名称，不保存完整 User-Agent 或原始 IP 地址。
- 邮箱验证链接 24 小时过期，密码重置链接 30 分钟过期；均为一次性令牌且数据库只保存摘要。
- 重置密码会撤销该账号全部旧会话；验证邮件和重置邮件同一账号一分钟内只发送一次。
- 正式生产还需要增加多因素认证、异常检测和网关级纵深限流。

## 应用层数据加密

应用使用一个部署环境提供的 `ENCRYPTION_MASTER_KEY`，通过带用途标签的 HMAC 派生彼此隔离的密钥。
AES-256-GCM 每次加密使用新的 96 位随机 nonce，并绑定上下文作为附加认证数据。

数据库内加密：

- 用户邮箱；
- 文档解析正文；
- 用户问题和系统回答；
- 回答引用摘录。

需要精确查询邮箱时使用单独派生密钥计算 HMAC 盲索引。UUID、外键、角色、状态和时间戳不加密，
因为授权、租户隔离和索引需要使用这些字段。企业名、文档标题和原始文件名当前仍属于可见元数据。

迁移 `20261021_0004` 会把已有知识正文、问题、回答和引用从旧明文格式原地转换为密文；读取逻辑仍能兼容迁移前数据，便于失败恢复。

## 文件加密

上传内容在内存中进行文件类型检查和解析，之后使用 AES-256-GCM 加密并保存为不可执行的 `payload.enc`。
文件的认证上下文包含企业、文档和版本 ID，因此把密文复制到其他记录下无法通过解密认证。
磁盘和对象存储中都不保存原始明文文件。生产环境使用私有 S3 兼容存储桶，应用只把稳定对象键保存到
数据库；服务商地址和凭据由部署环境注入。应用层加密始终保留，并可同时启用存储服务的服务端加密。

存储实现具有以下失败保护：

- 本地文件通过临时文件原子替换，拒绝绝对路径和目录穿越对象键；
- S3 凭据或存储桶配置缺失时拒绝启动；
- 对象写入失败时回滚当前数据库事务，不创建缺少原件的文档版本；
- 数据库提交失败时清理刚写入的对象；
- 存储桶不得开放匿名访问，服务账号只拥有目标存储桶的对象级最小权限。

## 密钥管理

- 公网环境缺少 `ENCRYPTION_MASTER_KEY` 时 API 拒绝启动。
- 密钥必须由 Render、云密钥管理服务或等价的机密存储注入，不能写入代码、镜像、日志或 Git。
- 备份数据库和对象存储时，还必须独立备份密钥；密钥丢失意味着密文不可恢复。
- 当前密文格式带 `v1` 版本标记，但自动轮换尚未实现。轮换前必须先增加多版本解密和后台重加密任务。

## 数据库基础设施

应用层加密不替代基础设施安全。正式环境还必须启用：

- PostgreSQL 托管磁盘加密与加密备份；
- TLS 数据库连接和最小权限运行账户；
- PostgreSQL 强制行级安全策略；
- 私有网络、访问日志、备份恢复演练和密钥审计；
- 持久对象存储，不能使用临时容器文件系统保存正式企业文件。

## 审计日志

- 身份、邀请、成员角色、空间授权、文档版本、发布和知识问答等关键操作与业务变更在同一事务中写入。
- 每次成功打开文档都会记录 `document.viewed`，包含空间、版本、发布状态和访问级别，但不记录文档正文。
- 越权但属于当前企业的请求记录为 `denied`；不存在的跨企业资源仍不写入可被探测的资源信息。
- 审计元数据不保存邮箱、密码、令牌、原始文件名、对象键、文档正文、问题、答案或引用摘录。
- 只有企业管理员拥有读取接口；查询仍受租户 RLS 限制。
- PostgreSQL 使用触发器拒绝审计记录的 `UPDATE` 和 `DELETE`，应用不提供修改或删除审计事件的 API。
- `AUDIT_RETENTION_DAYS` 默认 2555 天且不能短于 365 天；在完成不可变归档与独立维护角色之前，
  到期记录继续保留，不允许应用运行账户借保留任务删除证据。

数据库备份使用独立于应用主密钥的 AES-256-GCM 密钥，并在恢复前验证密文 SHA-256 和认证标签。
恢复演练只允许写入显式命名的隔离数据库。详细运行手册见
[备份、恢复演练与数据保留](06-backup-and-recovery.md)。

所有响应都带有经过格式验证的请求 ID、安全内容类型、禁止嵌入、无来源泄露和浏览器能力限制响应头；
非开发环境还启用 HSTS。访问日志不记录查询参数、正文、Cookie 或认证凭据。数据库就绪检查、配置
审计和告警建议见[生产运行、监控与配置审计](07-production-operations.md)。

## 尚未完成的生产门禁

- 多因素认证、企业 SSO 和 SCIM；
- 异常登录检测和管理员主动告警；
- 审计导出、不可变归档、外部 SIEM 对接和密钥自动轮换；
- 恶意文件扫描、上传对象备份恢复演练和自动完整性巡检；
- 线上备份调度、失败告警和至少一次有记录的实际恢复演练。

在这些门禁完成前，公网实例仍应被视为产品验证环境，不应上传真实机密资料。
