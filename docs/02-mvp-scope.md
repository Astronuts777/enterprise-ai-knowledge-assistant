# MVP 范围与验收标准

## 1. MVP 目标

验证不同企业是否愿意使用一个“有权限、有证据、有版本、有审计”的知识与决策系统，完成以下闭环：

> 企业资料进入知识空间 → 获得授权的员工提问 → 系统返回带精确引用的回答 → 系统暴露冲突、过期和证据缺口 → 负责人生成证据包 → 授权审批人确认、修改或拒绝。

MVP 不以覆盖所有行业和数据源为目标。行业无关体现在核心模型、权限机制和证据结构不绑定某一行业。

## 2. 首批目标组织

- 50–500 人的知识密集型企业。
- 文档分散在共享目录、PDF、Word、网页和会议记录中。
- 存在部门、项目或保密等级等权限边界。
- 对重要回答或决策有引用、版本和审计需求。

这是首发市场假设，不是永久行业限制，仍需通过真实访谈验证。

## 3. 核心角色

| 角色 | MVP 中的责任 |
| --- | --- |
| 企业管理员 | 创建企业、管理成员和企业级策略 |
| 知识管理员 | 创建知识空间、导入文档、维护版本和有效期 |
| 普通成员 | 在授权范围内搜索、提问和查看引用 |
| 项目或运营负责人 | 汇总证据并生成决策证据包 |
| 授权审批人 | 修改、批准或拒绝重要结论 |

一个用户可以拥有多个角色；权限由企业、知识空间、文档和操作共同决定。

## 4. P0：首个可交付版本

### 4.1 企业与知识空间

- 创建一个企业租户。
- 创建多个知识空间，例如“公司政策”“项目 A”“运营流程”。
- 为用户分配企业角色和知识空间角色。
- 所有业务记录必须包含 `tenant_id`，默认拒绝跨租户访问。

### 4.2 文档导入与版本

- 支持上传 PDF、DOCX、TXT 和 Markdown。
- 保存原始文件、内容哈希、上传人、来源、版本、有效期和敏感等级。
- 同一逻辑文档可以有多个版本，但只有明确标记的当前版本参与默认检索。
- 解析失败时显示可恢复的错误状态，不把失败文档标记为可查询。
- 网页抓取和第三方云盘连接不进入 P0。

### 4.3 权限内检索与问答

- 权限过滤必须发生在内容进入检索候选集之前。
- 同时使用关键词与语义检索，结果必须限定在用户可访问的文档版本内。
- 回答中的事实性主张必须关联至少一个引用。
- 引用至少包含文档名、版本、页码或段落定位及原文片段。
- 无足够证据时拒绝确定性回答，并说明缺少什么。

### 4.4 风险提示

- 引用过期内容时显示过期警告。
- 多个有效来源互相矛盾时显示冲突，不静默选择其中一个。
- 只能确认存在受限资料但不能暴露内容时，使用不泄露信息的提示语。
- 模型、解析器或检索服务失败时返回明确状态，不伪造答案。

### 4.5 决策证据包与人工确认

- 将一次问答转换为决策证据包。
- 证据包包含：问题、建议结论、支持证据、反对或冲突证据、未知项、风险、引用和生成时间。
- 证据包状态为草稿、待审核、已批准、已拒绝或已替代。
- 审批人可以修改结论，但原始 AI 输出必须保留。
- 批准记录包含审批人、时间、修改内容和备注。

### 4.6 审计与评测

- 记录文档上传、版本切换、权限变更、查询、检索结果标识、AI 输出和审批事件。
- 审计日志只记录必要元数据；默认不保存完整敏感提示词和文档正文。
- 建立一个小型黄金评测集，覆盖可回答、不可回答、冲突、过期和越权五类问题。
- 每次修改检索或生成策略后运行回归评测。

## 5. P1：验证 P0 后再加入

- 企业 SSO、SCIM 和自定义身份提供商。
- SharePoint、Google Drive、Notion 等连接器。
- OCR、扫描件和复杂表格解析。
- 自定义元数据模式和审批流程设计器。
- 多语言检索与回答。
- 通知、定期过期检查和知识负责人工作台。
- 行业知识包与行业评测集。

## 6. 明确不做

- 不做无限开放的通用聊天机器人。
- 不允许模型绕过权限读取“可能相关”的资料。
- 不让 AI 独立完成法律、医疗、财务、人事、安全等高风险决定。
- 不在 P0 支持所有文件格式、模型供应商和外部系统。
- 不承诺回答必然正确；系统承诺显示依据、限制和人工责任。

## 7. P0 验收场景

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 授权成员询问有效政策 | 返回答案、精确引用和版本信息 |
| AC-02 | 成员询问无权访问的资料 | 不检索、不引用、不暗示受限内容细节 |
| AC-03 | 两个有效来源结论冲突 | 显示冲突来源，不给出伪确定结论 |
| AC-04 | 唯一来源已经过期 | 标记过期并降低结论确定性 |
| AC-05 | 知识库没有答案 | 明确拒答并说明证据缺口 |
| AC-06 | 文档发布新版本 | 默认回答只使用当前版本，历史引用仍可追溯 |
| AC-07 | 负责人提交证据包 | 审批人可以修改、批准或拒绝，且保留完整变更链 |
| AC-08 | 管理员查看审计 | 能定位谁在何时执行了什么操作及其结果 |
| AC-09 | 跨租户请求 | API 和数据库两层均拒绝访问 |
| AC-10 | 回归评测 | 越权泄漏测试为零失败，事实性主张引用覆盖率为 100% |

## 8. 初始成功指标

以下是 MVP 验证指标，不是已验证的市场结论：

- 典型问题从发起到获得可核验证据的中位时间。
- 用户打开引用并确认原文的比例。
- 有足够证据的问题中，人工认为回答可用的比例。
- 无答案问题的正确拒答率。
- 冲突和过期来源的识别率。
- 权限回归测试中的越权结果数，目标必须为零。
- 证据包从草稿到人工决定的完成率。

## 9. 完成定义

P0 只有在以下条件全部满足时才视为完成：

1. 核心闭环可以在本地和测试环境运行。
2. 每个 P0 验收场景都有自动化或可重复的测试步骤。
3. 权限和租户隔离测试通过。
4. 引用可以回到稳定的原文位置。
5. 决策证据包保留 AI 输出与人工修改记录。
6. README、部署说明、数据模型和风险说明与代码一致。
