## 2026-10-21｜步骤 1：行业与目标用户选择

### 人类输入

从零开发一个有证据、有权限、可追溯，并保留重要决策人工确认机制的企业知识与决策辅助系统。先比较三个适合个人开发且有真实需求的垂直场景，并给出推荐。

### AI 输出摘要

AI 比较了建筑项目合同与规范助手、B2B 软件安全问卷助手、澳大利亚 NDIS 服务商合规助手，并建议以建筑行业作为首个垂直场景。

### 人工判断

拒绝。人类不希望把产品限定为单一行业，希望不同企业都能使用该知识库和 AI 决策助手。

### 拒绝原因

- 企业知识治理、权限、引用、版本、审计和人工确认属于跨行业共性能力。
- 将核心架构绑定到单一行业会限制后续扩展。

### 迭代结果

产品定位调整为“跨行业企业知识与决策证据平台”。核心平台不内置建筑、医疗或金融专属数据模型；行业差异通过可配置知识空间、元数据、权限策略、审批流程和评测集实现。

首个工作流暂定为“内部政策、流程、项目资料和会议记录的可信问答与决策证据包”。目标组织、购买者和具体场景仍需用户调研验证。

## 2026-10-21｜多租户与权限纵向切片

### 人类输入

确认继续开发企业知识库的下一步基础能力。

### 执行结果

- 建立企业、用户、企业成员和知识空间四个持久化模型。
- 建立创建企业、读取企业、管理成员、创建与列出知识空间的 API。
- 创建企业的首位用户自动成为企业管理员；成员只能读取知识空间，不能管理空间。
- 所有租户资源先解析当前用户在目标企业的服务端成员关系，再执行角色授权。
- 未授权用户访问其他企业时统一返回不泄露资源信息的 `404`。
- 加入 Alembic 初始迁移，并对企业、成员关系和知识空间启用 PostgreSQL 强制行级安全。
- 数据库运行账户 `app_runtime` 明确使用 `NOBYPASSRLS`，与迁移所有者账户分离。
- 在 Docker 不可用时，测试和本地体验使用 SQLite；生产数据库路径保持 PostgreSQL 兼容。

### 身份边界

当前 `X-Dev-User-Id` 只是本地开发身份适配器，不构成生产身份验证。接入企业 SSO 时，
必须用服务端验证后的身份声明替换该请求头，租户成员关系仍由数据库重新计算。

### 验证结果

- Python 测试共 13 项通过，包括跨租户管理员访问拒绝、成员只读和租户内唯一性。
- Alembic 可生成包含三张租户表 RLS 策略的 PostgreSQL 迁移 SQL。

## 2026-10-21｜证据式 AI 问答纵向切片

### 人类输入

确认开始下一阶段，让用户能够基于已发布的企业资料提问并获得带出处的答案。

### 执行结果

- 新增企业内问答和引用快照模型，问答历史按当前用户隔离。
- 建立只检索已发布版本的本地关键词检索器，支持中英文词项与中文双字匹配。
- 回答由相关原文摘录组成，每条结论带文档、版本、文件名和页码/段落定位。
- 未命中充分证据时明确返回“资料不足”，不调用外部模型，也不生成无来源结论。
- 支持限定单个知识空间提问；不存在或属于其他企业的空间不会扩大检索范围。
- 普通成员可使用问答能力，跨企业请求继续以不泄露资源信息的 `404` 拒绝。
- Web 控制台新增 AI 决策助手、问题输入、空间范围、建议问题、历史记录和引用卡片。
- 修复 PostgreSQL 事务提交后重新绑定租户上下文，确保强制 RLS 下提交后的读取仍受正确租户约束。

### 当前边界

本阶段优先验证可审计的产品闭环，暂不调用外部大模型。后续可将检索升级为关键词与向量混合检索，
并在引用契约、权限过滤和证据不足拒答保持不变的前提下加入生成模型。

### 验证结果

- Python API、权限、文档和问答测试共 24 项通过。
- Ruff、Web ESLint、TypeScript 与 Python 依赖完整性检查通过。
- Alembic 在全新 SQLite 数据库上升级至 `20261021_0003`，迁移一致性检查无差异。
- 隔离目录中的 Next.js Webpack 生产构建通过，API、Web 与 CORS 冒烟检查返回 HTTP 200。
- 浏览器端验证了有依据问题显示文档引用，以及无依据问题明确拒答两条流程。
