# 生产运行、监控与配置审计

## 三种不同的信号

系统把运行状态分成三个层次，避免“页面能打开”被误解为“已经满足企业生产要求”。

| 信号 | 用途 | 成功条件 |
| --- | --- | --- |
| `GET /healthz` | 容器存活检查 | API 进程能够响应 |
| `GET /readyz` | 流量就绪检查 | API 能够执行一次数据库查询 |
| `python -m enterprise_ai_api.operations` | 生产配置审计 | 全部强制企业控制均已配置 |

`/healthz` 不查询数据库，适合作为进程重启信号。`/readyz` 执行 `SELECT 1`，数据库不可用时返回 HTTP
503，适合作为部署完成验证和外部可用性监控信号。两个接口都不返回数据库地址、供应商账号或 Secret。

生产配置审计会检查：

- `APP_ENV=production`、HTTPS 公开地址和账号登录模式；
- PostgreSQL、独立应用加密密钥和持久 S3 文件存储；
- 强制邮箱验证与 SMTP 邮件后端；
- 独立备份加密密钥、持久 S3 备份存储和最低保留期。

执行命令：

```bash
PYTHONPATH=services/api/src:packages/core/src \
  .venv/bin/python -m enterprise_ai_api.operations
```

命令只输出布尔结果和修复提示，不输出任何 Secret。全部通过时退出码为 0，否则退出码为 1，可直接
作为发布流水线的生产门禁。公开演示环境预期不会通过，因为它仍使用临时文件存储、禁用真实邮件和
线上自动备份；这不会影响演示站正常启动。

## 请求追踪

每个 HTTP 响应都包含 `X-Request-ID`。客户端可以提供 8–64 位、只包含字母、数字、点、下划线或
连字符的请求 ID；非法值会被服务端替换。API 日志使用单行 JSON 记录：

- 事件名、请求 ID、HTTP 方法和路径；
- 状态码和处理耗时；
- 未处理异常的对应请求 ID。

日志不记录请求正文、查询参数、Cookie、Authorization、邮箱、问题内容或文档内容。用户报告错误时，
应收集响应头中的请求 ID，而不是索取密码或上传原件。

## 浏览器安全响应头

API 和同容器托管的 Web 页面统一返回：

- `X-Content-Type-Options: nosniff`；
- `X-Frame-Options: DENY`；
- `Referrer-Policy: no-referrer`；
- 禁用摄像头、麦克风和定位的 `Permissions-Policy`；
- 非开发环境启用一年期 `Strict-Transport-Security`。

严格 CSP 需要先给 Next.js 内联引导脚本增加 nonce，因此暂不以一个可能破坏登录页面的策略冒充完成。
在引入第三方分析、模型流式接口或外部静态资源时，应同时完成 nonce CSP 和依赖域名审查。

## 建议告警

正式环境至少配置以下外部告警：

| 告警 | 建议条件 | 初始处理 |
| --- | --- | --- |
| 服务不可用 | `/readyz` 连续 3 次返回非 200 | 检查数据库和最近部署，必要时回滚 |
| 错误率 | 5 分钟内 5xx 超过 2% | 按请求 ID关联日志，冻结高风险发布 |
| 延迟 | 5 分钟 P95 超过 2 秒 | 检查数据库连接、慢查询和外部依赖 |
| 备份失败 | 每日任务超过 26 小时没有成功清单 | 修复任务后补做备份并验证清单 |
| 恢复演练逾期 | 35 天内没有成功演练记录 | 创建隔离库并执行完整恢复演练 |
| 存储容量 | 数据库或对象存储超过 80% | 扩容并检查异常增长来源 |

告警必须发送到有人值守的渠道，并明确负责人、升级路径和维护窗口。仓库不会自行假设 Slack、邮件、
PagerDuty 或其他供应商，也不会在未配置接收人时声称告警已启用。

## 发布验证

每次生产发布至少执行：

```bash
curl --fail --show-error https://<host>/healthz
curl --fail --show-error https://<host>/readyz
```

然后完成一次登录、企业/空间授权读取和只读知识查询。数据库迁移、加密格式、对象存储或认证变更还应
执行针对性的回归测试。发布失败时保存部署 ID、Git commit 和请求 ID，再回滚到最近一次已验证版本。

企业管理员可从审计页面导出 CSV 合规快照。导出接口复用企业级授权和 MFA 策略，单次最多 5000 行；
超过上限时应缩小时间范围或筛选条件。每次成功或超限失败的导出都留下审计事件，便于复核证据链。
