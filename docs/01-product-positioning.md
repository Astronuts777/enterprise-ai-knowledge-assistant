# 产品定位（草案）

## 一句话定位

帮助企业把分散文档转化为一个有权限、有证据、有版本、有审计记录的知识与决策系统。

## 首批目标组织

暂定为 50–500 人、内部知识分散、多人协作、存在权限层级，并需要为重要回答或决策保留证据链的企业。

这一定义用于控制首发市场和调研范围，不构成行业限制。

## 核心角色

| 角色 | 主要任务 |
| --- | --- |
| 普通员工 | 在权限内查找可信答案和原文依据 |
| 项目或运营负责人 | 汇总证据、比较方案、识别冲突和缺口 |
| 合规或质量负责人 | 管理版本、有效期、敏感信息和审批要求 |
| 知识管理员或 IT | 管理数据源、权限、索引、审计和配置 |
| 授权审批人 | 对重要结论进行修改、批准或拒绝 |

## 首个跨行业工作流

内部政策、流程、项目资料和会议记录的可信问答与决策证据包。

## MVP 能力假设

1. 导入 PDF、Word、网页和会议记录。
2. 按企业、知识空间、项目、文档和用户执行权限控制。
3. 回答时提供来源、版本和精确位置。
4. 识别文档冲突、过期内容和证据不足。
5. 生成包含方案、支持证据、反对证据、风险与未知项的决策证据包。
6. 由人确认重要结论，并保留修改与批准记录。

## 待验证问题

- 哪类企业最愿意为可信问答和决策追溯付费？
- 日常查询与重要决策分别由哪些角色发起？
- 企业目前如何判断文档是否有效、最新和可访问？
- 哪些错误会造成最大业务损失？
- 客户是否愿意把敏感文档交给云端服务？
