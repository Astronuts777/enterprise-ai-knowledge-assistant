# 用户故事与核心流程

## 1. 体验原则

- 先确认身份和权限，再进行检索。
- 先展示结论限制，再展示流畅措辞。
- 每个重要事实都能回到原文。
- 冲突、过期和未知项是正式结果，不是系统错误。
- AI 生成建议，人类对重要决定负责。

## 2. 核心流程 A：建立可查询知识空间

1. 企业管理员创建企业并邀请知识管理员。
2. 知识管理员创建知识空间，设置成员和默认敏感等级。
3. 知识管理员上传文档并补充来源、版本和有效期。
4. 系统计算文件哈希、保存原件、解析文本并建立定位信息。
5. 系统切分内容、生成检索表示并执行权限继承。
6. 管理员查看解析预览，确认后将文档版本发布为可查询。

失败或未确认的文档保持草稿状态，不进入默认问答。

## 3. 核心流程 B：可信问答

1. 成员选择知识空间并输入问题。
2. 系统计算其企业、空间和文档权限。
3. 系统只在授权且可用的文档版本中执行混合检索。
4. 系统分析来源是否过期、互相冲突或证据不足。
5. 模型基于允许的证据生成结构化草稿。
6. 引用校验器检查每个事实性主张是否有有效出处。
7. 用户获得回答、置信状态、引用、风险提示和“生成证据包”入口。

## 4. 核心流程 C：决策证据包

1. 项目或运营负责人将问答转换为证据包。
2. 系统整理建议结论、支持证据、反对证据、未知项和风险。
3. 负责人编辑背景与备选方案并提交审核。
4. 审批人检查引用，可修改结论、批准或拒绝。
5. 系统冻结该次决定的证据快照并记录完整审计事件。
6. 如果引用文档后来被替代，历史决定仍指向当时使用的版本，同时显示新版本提示。

## 6. 权限矩阵

| 操作 | 企业管理员 | 知识管理员 | 普通成员 | 负责人 | 审批人 |
| --- | --- | --- | --- | --- | --- |
| 管理企业成员 | 是 | 否 | 否 | 否 | 否 |
| 创建知识空间 | 是 | 是 | 否 | 否 | 否 |
| 上传和发布文档 | 可配置 | 是 | 否 | 否 | 否 |
| 查询授权内容 | 是 | 是 | 是 | 是 | 是 |
| 创建证据包 | 可配置 | 可配置 | 否 | 是 | 是 |
| 提交证据包 | 可配置 | 否 | 否 | 是 | 是 |
| 批准或拒绝 | 可配置 | 否 | 否 | 否 | 是 |
| 查看企业审计 | 是 | 限知识空间 | 仅本人活动 | 仅相关证据包 | 仅相关证据包 |

矩阵表示默认策略；最终授权由角色、知识空间成员关系、文档规则和操作策略共同计算。

## 7. 回答状态模型

| 状态 | 用户可见行为 |
| --- | --- |
| 有充分证据 | 给出回答和逐项引用 |
| 证据有限 | 给出有限结论，明确未知项 |
| 来源冲突 | 并列冲突观点和出处，请人判断 |
| 来源过期 | 显示过期时间，不把它描述为当前规则 |
| 没有证据 | 拒答并建议补充资料或咨询负责人 |
| 权限不足 | 不透露受限资料名称、数量或内容细节 |
| 系统失败 | 显示可重试错误，不生成替代答案 |

## 8. 决策证据包最小结构

```text
问题与背景
建议结论
备选方案
支持证据[]
反对或冲突证据[]
未知项[]
风险[]
引用快照[]
AI 生成信息
人工修改记录[]
审批记录[]
状态与版本
```

## 9. 仍需用户调研验证

- “普通成员”和“负责人”是否需要分离为两个角色。
- 哪种文档最常被错误版本误导。
- 用户更愿意先搜索还是直接提问。
- 重要决定的真实审批链有几级。
- 企业可以接受哪些内容发送给外部模型服务。
