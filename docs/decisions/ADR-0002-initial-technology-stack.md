# ADR-0002：MVP 初始技术栈

- 状态：已接受
- 日期：2026-10-21
- 决策范围：MVP 开发与本地运行

## 背景

本项目需要同时处理企业级权限、文档解析、语义检索、模型调用、引用校验和异步任务。团队当前以个人开发为主，因此技术栈必须在可信边界和开发效率之间取得平衡，避免过早引入微服务、专用向量数据库和复杂消息基础设施。

## 提议

### 应用技术

| 层 | 选择 | 原因 |
| --- | --- | --- |
| Web | Next.js App Router + TypeScript | 适合构建带服务端会话的企业 Web 界面，路由、加载和错误边界完整 |
| API | FastAPI + Python | 类型化 API、OpenAPI 契约，并便于复用 Python 文档与 AI 工具生态 |
| Worker | Python Worker，共享 API 领域包 | 解析和嵌入任务与 HTTP 生命周期分离 |
| 数据库 | PostgreSQL | 统一保存业务数据、权限关系、全文索引、审计元数据和任务状态 |
| 向量检索 | pgvector | 在同一事务和租户过滤条件下执行向量检索，降低早期系统复杂度 |
| 文件存储 | S3 兼容对象存储 | 保存不可变原件和解析产物，本地可使用兼容实现 |
| 异步任务 | PostgreSQL 任务表 + `FOR UPDATE SKIP LOCKED` | P0 减少 Redis 或消息队列依赖；任务必须幂等 |
| 模型接入 | 自有供应商适配器 + 官方 SDK | 保持供应商可替换并完整记录模型运行元数据 |
| 可观测性 | OpenTelemetry + 结构化日志 | 统一请求、任务、检索和模型调用的追踪上下文 |
| 本地环境 | Docker Compose | 一条命令启动 PostgreSQL 和对象存储等依赖 |

具体依赖版本在代码脚手架创建时锁定，不在 ADR 中使用浮动的“最新版”。

## 架构形态

采用模块化单体加独立 Worker，而不是微服务：

- Web、API 和 Worker 是三个可独立运行的进程。
- 领域规则集中在 API/领域包中，权限策略不复制到前端。
- PostgreSQL 是业务事实来源，对象存储保存大文件。
- 模型供应商通过端口接口接入，不允许供应商 SDK 类型渗入核心领域模型。

## 关键实现约束

1. PostgreSQL 行级安全用于纵深防御，但不能替代应用层授权。
2. 应用数据库角色不得拥有表所有权、超级用户或 `BYPASSRLS`。
3. pgvector 查询必须在租户和授权条件内执行。
4. P0 优先精确检索；只有评测证明需要时才启用近似索引。
5. FastAPI 的进程内后台任务不用于耗时解析；文档任务由独立 Worker 领取。
6. 前端不持有对象存储、数据库或模型供应商密钥。
7. 生成与嵌入分别定义接口，允许使用不同供应商。

## 被否决或推迟的方案

### 全部使用 Next.js

优点是单语言和单部署单元。暂不采用，因为文档解析、评测和 AI 数据处理更适合 Python 生态；把耗时处理放进 Web 运行时也会模糊职责边界。

### 从第一天使用专用向量数据库

可能在大规模检索时更灵活。P0 推迟，因为它增加数据同步、权限过滤和运维复杂度；先用真实数据和评测证明 PostgreSQL 无法满足需求。

### 从第一天使用 Kubernetes 和微服务

可以提供更强的独立扩缩容。P0 推迟，因为当前产品风险大于扩展风险，复杂部署会降低验证速度。

### 直接依赖大型 AI 编排框架

可以快速组合组件。P0 不将其放在核心路径，因为权限、检索、提示模板和引用校验需要显式可审计；可以在非核心实验中使用。

## 影响

### 正面影响

- 业务权限与向量过滤可以在一个数据库事务边界内完成。
- Python 负责文档和 AI 工作负载，TypeScript 负责 Web 体验，职责清晰。
- 初始基础设施较少，个人开发可以维护。
- 后续可以替换模型、对象存储或任务系统而不改变证据模型。

### 代价与风险

- 两种语言增加工具链和契约同步成本。
- pgvector 在多租户近似检索下需要仔细评估召回率。
- PostgreSQL 任务表不适合无限增长和极高吞吐。
- 行级安全配置错误可能造成错误的安全感。

### 缓解措施

- 以 OpenAPI 生成前端客户端，减少手写重复类型。
- 为每个权限规则建立负向测试和跨租户测试。
- 在黄金评测集上比较精确检索与近似检索。
- 当任务积压和吞吐达到明确阈值后，再用 ADR 决定是否迁移消息队列。

## 确认结果

人类于 2026-10-21 确认采用该技术栈。下一步创建最小代码骨架、锁定依赖版本，并优先用跨租户拒绝和角色拒绝测试验证权限边界，而不是立即实现全部 P0 功能。
