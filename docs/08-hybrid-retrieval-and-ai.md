# 混合检索与可配置 AI

## 1. 默认行为

系统默认使用本地关键词检索和原文摘录回答：

- `AI_PROVIDER=local`
- `EMBEDDING_PROVIDER=disabled`
- `AI_ALLOW_RESTRICTED=false`

因此，默认部署不会因问答或上传文档而调用外部模型。公开演示环境也固定使用这一模式。

## 2. 权限与数据流

问答先根据服务端身份计算用户可访问的知识空间，再查询其中已发布的文档版本。任何关键词匹配、
语义排序和生成模型调用都发生在这个授权候选集之后，不会先检索全企业数据再丢弃越权结果。

启用外部嵌入后，系统在上传或手动重建索引时向供应商发送解析后的文档块；启用外部回答后，系统
向供应商发送问题和本次检索到的少量证据片段。不会发送整库内容、未发布版本、其他企业数据、
API 密钥、数据库凭据或用户会话。Responses 请求设置 `store=false`，但企业仍需自行评审供应商的
合同、地域、日志、滥用监控和数据保留条款。

`restricted` 空间默认禁止外部嵌入和外部回答。即使同时查询多个空间，只要范围中包含严格受限空间，
本次问题就保守回退到本地检索与本地证据回答。只有企业完成风险评审并明确配置
`AI_ALLOW_RESTRICTED=true` 后才解除这一限制。

## 3. 混合检索

每个文档块可以保存一个模型名称和一组嵌入向量。向量使用与正文相同的 `EncryptedText` 类型，在
写入数据库前由 AES-256-GCM 认证加密。查询时，应用只读取当前租户、当前授权空间和已发布版本的
候选块，解密匹配模型的向量，计算余弦相似度，再与关键词覆盖分数组合。只有语义相似度达到最低
阈值的纯语义命中才会成为证据。

关键词检索同时匹配正文、文档标题和版本文件名。订单号、合同号、项目代码等高辨识度的拉丁字母、
数字、连字符或下划线标识符会获得额外权重，不会因为中文自然提问中的礼貌用语而被覆盖率门槛清零。
仅由标题或文件名命中时只选取该版本的首个正文块，避免同一文档的元数据把所有块同时推入结果。

已移除“先按创建时间截取最新 5,000 块”的召回上限。现在 SQL 先限定企业、授权空间和已发布版本，
再通过 SQLAlchemy `yield_per` 每批读取 256 块，遍历此次查询可见的全部授权候选。256 是批大小，
不是总量上限；不以 OFFSET 翻页，也不把全量明文或匹配结果装进列表。

扫描过程中只保留全局最优 4 块与最优 4 份不同文档的代表块，优先保证文档多样性，不足 4 份时补充全局候选。
分数相同按标题、段落位置和稳定片段 ID 排序，结果不依赖批次边界。扫描游标关闭后，使用相同的权限/发布条件
再次按同样的过滤条件读取代表块及其前后相邻位置，最终最多返回 8 条引用。
正文和向量仍采用应用层加密，没有新增明文索引、付费服务或数据库迁移。

这是**消除静默遗漏并控制应用内存**的修复，不是大规模索引加速：查询仍需逐一解密和评分，耗时随授权片段数量增长，
数据库驱动缓冲和并发负载也需验收。中途读取/评分异常不会返回一个伪装成完整检索的部分答案。
`services/api/tests/test_retrieval_streaming.py` 使用超过 5,000 块验证旧来源、文件名/语义命中、相邻上下文、
全匹配时零 ORM 评分对象与有界摘录次数、权限过滤和跨批次排序；语义测试用固定向量，不等于真实模型质量评测。
可用 `RETRIEVAL_TEST_DATABASE_URL` 在专用、已迁移且已授权的 `enterprise_retrieval_test` 数据库上运行该文件，
禁止指向业务库；测试会写入合成资料但不会自动清库。本轮本机 PostgreSQL 初始化受共享内存权限限制，未完成其实际运行验收。

### 查询路径性能优化

评分阶段改为标量字段投影，保留的候选仅包含 ID、标题、位置及分数，不再为每块创建完整文档/版本/空间 ORM 对象。
纯关键词查询不选择向量列；混合查询用 SQL CASE 仅返回模型匹配的向量，仍由 `EncryptedText` 认证解密。
查询向量范数移到循环外计算。扫描结束后，以相同的租户、空间、发布过滤再次读取最多 12 个候选/邻居，
此阶段不加载任何向量；只为最终最多 8 个片段生成摘录，而不是为每个命中片段生成摘录。
扫描期间已撤回的版本不会被作为引用返回，生成后及引用阅读时原有的权限/来源复核不变。

不新增跨请求结果或明文特征缓存，避免权限变更、重新建索引和密钥变更后的缓存失效问题。
原文、向量、文件加密格式和密钥均不变；关键词查询不读取的向量不做完整性检查，
实际参与语义评分的向量若密文损坏仍然报错，不静默生成部分结果。

2026-10-22 本机 SQLite 内存库、5,011 个 AES-GCM 加密片段（正文约 3,150 字符、768 维合成向量）：
对比已部署旧提交 `2db1307`，每种场景交替运行新旧实现 3 次，取检索函数墙钟时间中位数。

| 场景 | 旧实现 | 新实现 | 加速比 |
| --- | ---: | ---: | ---: |
| 关键词，少量命中 | 0.7217 秒 | 0.4760 秒 | 1.52× |
| 关键词，大量命中 | 1.4843 秒 | 0.5428 秒 | 2.73× |
| 混合，少量命中 | 1.4251 秒 | 1.1916 秒 | 1.20× |
| 混合，大量命中 | 2.2797 秒 | 1.2377 秒 | 1.84× |

四种场景逐条验证引用 ID、顺序、词法/语义/最终分数、摘录和密级一致。复现：

```bash
BENCHMARK_RETRIEVAL=1 .venv/bin/pytest services/api/tests/test_retrieval_performance.py -s
```

该 opt-in 测试需要本地 Git 历史包含旧提交；仅使用隔离 SQLite，若设置非 SQLite 的
`RETRIEVAL_TEST_DATABASE_URL` 则跳过。常规 CI 不把墙钟比例当作易抖动的断言，
而是验证无 ORM 扫描、有界摘录、跳过无关向量、密文不被改写以及撤回与访问隔离。
本轮完整后端测试 188 通过、3 跳过（真实 OCR、真实模型和 opt-in 性能测试）；性能测试另行运行通过。
前端类型检查、lint 和静态构建通过。测试不包含真实模型耗时、并发负载、磁盘数据库 I/O 或 Render 资源限制；
没有完成真实 PostgreSQL 大库性能验收。O(N) 复杂度仍然存在，不能据此承诺无限扩容或固定响应时间。

实现刻意没有把明文向量交给数据库索引，因此不能获得 pgvector 的大规模近邻检索性能。进入大规模生产前，需要在
以下方案中作出明确的数据保护决策：

1. 接受数据库可读取向量的风险，在 PostgreSQL RLS 条件内使用 pgvector；
2. 为每个租户部署隔离的向量服务或数据库；
3. 使用支持可验证访问控制的托管检索服务；
4. 保持应用层加密，并按空间或文档建立受限的缓存与分片。

无论选择哪一种，都必须先做租户过滤后的召回率、跨租户隔离和权限变更回归测试。

## 4. 生成与引用校验

外部回答适配器使用严格 JSON Schema，要求模型返回“证据是否充分”和一组“主张 + 引用编号”。
模型返回的文本不是可信数据，服务端会：

1. 拒绝未知字段、空主张和没有引用的主张；
2. 拒绝任何超出本次候选证据范围的编号；
3. 删除模型自行写入的 `[数字]` 标记；
4. 只保留实际使用的证据，并由服务端连续重新编号；
5. 在模型不可用或输出不合规时返回 503，并写入不含正文的失败审计事件。

本地模式不生成新事实，只拼接相关原文摘录。两种模式在证据不足时都明确拒答。

结构化输出和嵌入请求分别参照 OpenAI 官方的
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)
与 [Embeddings API](https://developers.openai.com/api/reference/python/resources/embeddings/methods/create)。

## 5. 配置与启用

在部署平台的 Secret 管理器中设置，不要写入 Git：

```dotenv
AI_PROVIDER=openai
AI_MODEL=<approved-response-model>
EMBEDDING_PROVIDER=openai
EMBEDDING_MODEL=<approved-embedding-model>
OPENAI_API_KEY=<secret>
AI_ALLOW_RESTRICTED=false
```

可选设置 `OPENAI_PROJECT`、`OPENAI_BASE_URL`、`EMBEDDING_DIMENSIONS` 和
`AI_REQUEST_TIMEOUT_SECONDS`。生产环境的自定义 Base URL 必须使用 HTTPS。配置缺少密钥或模型名称
时应用拒绝启动，不会悄悄降级到未授权的供应商。

新上传文档会自动建立语义索引。已有文档由知识管理员调用：

```text
POST /v1/tenants/{tenant_id}/document-versions/{version_id}/semantic-index
```

重建会替换该版本所有文本块的向量和模型名称，并写入审计事件。嵌入失败不会写入部分结果。

## 6. 上线验收

- 用同义词问题验证纯关键词无法命中而语义检索可以命中；
- 查看数据库原始列，确认嵌入以 `enc:v1:` 密文保存；
- 验证无权用户、未发布版本和其他企业内容不会成为候选证据；
- 验证模型伪造或越界引用被拒绝；
- 验证 `restricted` 空间不会产生外部 provider 调用；
- 验证供应商超时返回通用错误，日志和审计中没有问题正文或证据正文；
- 建立包含可回答、不可回答、冲突和权限变化的离线评测集后再扩大使用范围。
